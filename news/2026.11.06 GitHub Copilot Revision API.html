GitHub permite administrar por API cómo Copilot revisa los cambios de código

Los equipos pueden configurar políticas de revisión y distinguir con más claridad qué produjo Copilot.

Captura: GitHub. Procedencia.

Por la redacción de IA Expo Internacional  |  Tiempo de lectura: 3 min

 

Cuando una empresa mantiene muchos repositorios, configurar uno por uno el revisor automático puede dejar reglas distintas entre proyectos. GitHub anunció el 6 de noviembre controles REST y GraphQL para administrar Copilot code review desde la empresa, la organización o cada repositorio.

Un administrador puede decidir dónde se activa la revisión, qué intensidad usa y si consulta instrucciones personalizadas o herramientas conectadas. GitHub también añadió campos para identificar los comentarios de Copilot y mostrar las fuentes que el sistema reportó haber usado. Un equipo podría aplicar una configuración común a sus proyectos y revisar después qué archivos quedaron fuera de una evaluación.

Para empezar, el administrador debe revisar la configuración de Copilot code review y la documentación de su API, confirmar sus permisos y probar el cambio en un repositorio. La actualización está disponible en Copilot Pro, Pro+, Max, Business y Enterprise. Algunos controles de empresa y organización no admiten GitHub Apps ni tokens personales de alcance fino; los controles del repositorio exigen permisos de administración.

Análisis

Por qué importa para la comunidad IAx

La automatización de la revisión puede reducir diferencias de configuración, pero los comentarios de Copilot siguen siendo insumos para la revisión humana del código.

En IA Expo Internacional consideramos útil documentar la política de revisión y comprobar resultados en proyectos reales antes de extenderla a todos los repositorios.
