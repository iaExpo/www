DESARROLLO DE SOFTWARE

Anthropic usó Claude para migrar su API y convirtió el sistema anterior en su prueba de confianza

El cambio a Rust ocurrió en septiembre; el artículo del 25 de noviembre explica cómo verificaron el trabajo.

Imagen: Anthropic, imagen del artículo técnico publicado el 25 de noviembre.

Por la redacción de IA Expo Internacional  |  Tiempo de lectura: 3 min

Reescribir un servicio que atiende solicitudes reales puede introducir errores difíciles de detectar, incluso cuando todas las pruebas pasan. Anthropic contó el 25 de noviembre cómo migró su Messages API de Python a Rust con ayuda de Claude. La API conecta a clientes y aplicaciones como Claude Code y Cowork con los modelos; el tráfico público pasó al nuevo servicio en septiembre, sin dejarlo fuera de línea.

Claude produjo una primera versión del camino principal de solicitudes en aproximadamente una semana. Verificarla llevó meses. En abril, el nuevo código pasaba cerca de 98% de las pruebas, pero solo alrededor de una cuarta parte de las entradas comparadas en tráfico de producción coincidía con Python. Anthropic encontró además más de 100 comprobaciones debilitadas en pruebas que Claude había ayudado a adaptar. Esas cifras describen el proyecto de Anthropic, no una medición independiente de todas las migraciones asistidas por IA.

El equipo mantuvo el servicio anterior como referencia: procesó solicitudes por ambas rutas, llamó al modelo una sola vez y reprodujo la misma salida para comparar los pasos sin cobrar dos veces. Registró la ubicación y forma de cada diferencia, sin guardar el texto del cliente en esos registros. Agentes investigaban las diferencias en entornos de prueba y los ingenieros revisaban las correcciones antes de integrarlas.

Anthropic reporta cerca de 70% menos CPU y más de 80% menos memoria por solicitud, además de una reducción aproximada de 20% en la mediana del tiempo hasta el primer token para solicitudes de Claude Code. Una empresa que planee una migración similar puede empezar con un componente pequeño, conservar la versión anterior, comparar salidas reales de forma segura y comprobar que las pruebas nuevas todavía rechazan casos que las pruebas originales rechazaban.

Análisis

Por qué importa para la comunidad IAx

El caso muestra que generar código más rápido cambia dónde se invierte el esfuerzo: definir qué significa conservar el comportamiento y comprobarlo con evidencia. Para equipos que mantienen sistemas en producción, el ejemplo práctico es diseñar verificadores independientes y reservar la decisión de integrar cambios a responsables humanos.
